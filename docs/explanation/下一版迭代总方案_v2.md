## 第 1 部 · 三团队 critique

> 方法论: 每个设计师以"说出具体问题 + 给出具体解法"为准则。引用真实作品/真实人物, 但 critique 是模拟 (基于他们公开的设计哲学推导出他们会如何看 HGC)。

### 1.1 · 团队 A · Top 100 工作软件设计师 · 22 条 critique

#### A-01 · Karri Saarinen (Linear CEO · 访谈 "Design is search")

> 问题: "/internal/dashboard 顶部 4 个 KPI 卡是静态的方块 — 没有时间维度。在 Linear Cycles 视图中, 每个 KPI 下有 sparkline 表示过去 7 天趋势。静态数字是 observability 的最低级形式。"
>
> 方案:
> ```
> [ 现在 ]                     [ 改后 ]
>                              ┌──────────────────┐
>   ┌──────────┐              │ 156 clips        │
>   │ 156 clips │              │ ▁▂▄▅▇▅▆ +12%    │
>   │          │              │ hover→展开大卡片 │
>   └──────────┘              └──────────────────┘
>   (只是数字)                 (sparkline + trend)
> ```
> Why: Saarinen 说 "the way design is constructed doesn't matter — the data does." KPI 如果没有时间线, 就是死数据。

#### A-02 · Karri Saarinen (Linear)

> 问题: "你们没有真正的 Cmd+K 命令面板。Linear 可以 3 秒内建 issue、切视图、跳项目, 靠的是 ⌘K。HGC 现在要找一个菜谱, 要点侧边栏 → tools → recipe → 滚。4 步 > 1 步。"
>
> 方案: 全局 Cmd+K
> ```
> ⌘K   [🔍 search anything...]
> ─────────────────────────────────
>  Recent
>   📋 O-04 Trade Show 菜谱
>   🎞  /library/triage
>  Actions
>   ⚡ Create recipe
>   ⚡ Import clip (Cmd+U)
>   ⚡ Switch channel (Choice/Snacks/PR)
>  Navigate
>   → Dashboard           (Cmd+1)
>   → Library             (Cmd+2)
>   → Recipes             (Cmd+3)
>   → Triage              (Cmd+T)
> ```

#### A-03 · Rahul Vohra (Superhuman CEO · "100ms rule")

> 问题: "从 /library 点击一个视频, 到进入 /split/[id] · 等了 2-3 秒。这违反 100ms 原则。Paul Buchheit 的 Gmail 原话: 'Every interaction should be faster than 100ms.' 2-3 秒是手感断裂的终结。"
>
> 方案:
> 1. Split 页改成 intercepting routes (Next.js 16) · 点击即 modal 预览 · 背景保留 library 上下文
> 2. HLS preload=metadata · hover 时就开始 fetch m3u8
> 3. `viewTransition` API · 标签变色 → 下一帧页面结构已建好

#### A-04 · Rahul Vohra (Superhuman)

> 问题: "你们没有 keyboard hint 覆盖层。Superhuman 按 ? 会弹出 '当前能按的所有键' 的浮窗。HGC 在 /library/triage 只在底部写了小字 'Q W E R T Y U I O P'。新人第一次来完全看不懂。"
>
> 方案: 按 `?` 弹出半透明 overlay, 高亮所有 actionable 键。关闭时 overlay 淡出。

#### A-05 · Josh Miller (Arc Browser founder · 访谈)

> 问题: "Arc 教会我们一个教训 (Miller 亲口说的): '太复杂, 太多新东西要学, 奖励太小'。HGC /internal 侧边栏有 9 个入口, 但 3 个是空页面 (intel, learn, chat, publish, monitor)。这是 Arc 的最大错误的翻版。"
>
> 方案: 空页面隐藏或打 `soon` 灰色标。不要让用户点进去发现一片空白 — 这是信任的流失。

#### A-06 · Ryo Lu (Notion → Cursor · Dive Club Ep 36)

> 问题: "Notion 的 block paradigm 要求每个元素是 first-class, 可拖可重组。HGC 的菜谱页 /tools/recipe/[id] 是只读的 markdown render。菜谱应该是 block — 每一步骤 (开场/主体/结尾) 可以拖, 可以 inline 编辑。"
>
> 方案: 菜谱详情页用 block editor (TipTap / ProseMirror). 每个步骤是独立 block, 拖拽重排。参考 Linear 的 project detail page。

#### A-07 · Thomas Paul Mann (Raycast CEO · dive.club)

> 问题: "Raycast 最强的是 '一个入口, 所有上下文'。HGC 现在有 6 个入口 (侧边栏 9 项 + Cmd+K 没有)。Raycast 让 launcher 成了 OS。HGC 的 Cmd+K 应该包括: 搜素材、搜菜谱、搜成员、搜操作、搜 Freddy 人设片段。"
>
> 方案: Cmd+K 分组 — recent / actions / navigate / search content · 每组可键盘 Tab 切换 · Enter 执行。

#### A-08 · Evan Wallace (Figma co-founder · 2019 博客)

> 问题: "Figma 的灵魂是 'multiplayer 是自然而然的'. HGC /library/triage 是单人。如果 Frida 和 Hank 在同一时间打标, 他们互相看不见。"
>
> 方案: Supabase Realtime Presence · 添加他人的彩色光标 · 头像角标在每个正在被看的卡片。

#### A-09 · Ohad Eder-Pressman (Figma early design)

> 问题: "Figma 的 Inspect Panel 把 CSS/measurements 放在右侧固定栏。HGC /split/[id] 的元信息 (duration, tags) 散落在各处。"
>
> 方案: 右侧 fixed Inspect Drawer, 240px 宽, Cmd+\ 切换。显示: 时长 / AI 标 / 人工标 / 使用在哪几个菜谱 / 引用次数。

#### A-10 · Jason Fried (Basecamp · "Shape Up")

> 问题: "你们的 dashboard 把 HGC Overview 和 KPI 和 Freddy 卡放一行 — 这是 dashboard blindness。Shape Up 主张: 一个页面一个决定。"
>
> 方案: Dashboard 第一屏只放一个卡 — **Today's Decision** · 内容是今天最重要的待决策 (例: "O-04 菜谱待你审 3 条") · 其余折叠到下方。

#### A-11 · Alex Ford (Things 3 · Cultured Code)

> 问题: "Things 3 因为每一个 checkbox 的勾选都有 '微小但被精心设计的' 动画 (0.3s spring + haptic) 得了 2 次 Apple Design Award。HGC 的 recipe 菜谱页点击 'mark done' 什么都没发生 · 只是颜色变灰。"
>
> 方案: 使用 motion (ex-Framer Motion) · spring(stiffness: 400, damping: 30) · 配合 `Audio('/sfx/check.mp3')` 短促木质声 (已有 sfx.ts 架构)。

#### A-12 · Mitch Cohen (1Password 8 product director · "Knox" design system)

> 问题: "1Password 8 Quick Access 是一个浮层, Cmd+Shift+Space 触发, 所有行动可达。HGC 现在要查 Freddy 某个档案要先 /internal/dashboard 滚下去。"
>
> 方案: 复用 Cmd+K, 但加 '人物快速卡': 输入 'Freddy' 立刻弹完整卡片 (头像/设定/正在做/TODO), 不跳页。

#### A-13 · Andy Matuschak (ex-Apple · spaced repetition / Orbit 作者)

> 问题: "HGC 完全没有 '学习' 循环。Library 收了 156 clips, 但没有'最近 30 天没被回看的'提醒。这是 cold storage, 不是 working memory。"
>
> 方案: Dashboard 加 '久违素材' 卡片 — 随机 3 个 30+ 天未用的 clip, 每天刷新一次。触发新的创意。

#### A-14 · Isaac Hester (Craft app designer)

> 问题: "Craft 用 'material texture' (纸质阴影, 阴影的层次) 表达文档的实体感。HGC 用 `shadow-none`, 全部是 flat 色块, 丢失了 MUJI × Rodchenko 应有的'纸'的厚度。"
>
> 方案: 为每个卡片加 2px 的 paper-deep 阴影 + 在 card-hover 时添加 0.5px inset ring。使用 `shadow: 0 1px 2px rgba(74,66,45,.08), 0 0 0 1px rgba(74,66,45,.04) inset`.

#### A-15 · Maggie Appleton (Obsidian power user · 数字花园)

> 问题: "Obsidian 的 Graph View 是让 power user 看见结构的关键。HGC 的 156 clips 之间一定有关系 (同菜谱/同日期/同 Freddy 表情), 但没有可视化。"
>
> 方案: /library 顶部加切换 "List | Grid | Graph" · Graph 视图用 force-directed layout (d3-force / react-force-graph), 节点颜色 = 来源 (Choice/Snacks/PR), 边 = 共同 tag。

#### A-16 · Tristan Homsi (Readwise Reader co-founder · Metamuse Ep 79)

> 问题: "Reader 的核心是 '每一个格式 (文章/PDF/YouTube/推特) 都同一个阅读界面'. HGC 现在视频和图片的处理页完全不同。"
>
> 方案: /library 内统一的 MediaViewer 组件 — 视频用 hls.js, 图片用 Image Viewer, PDF 用 pdf-js, 但 metadata panel / actions 完全相同。

#### A-17 · Zach Lloyd (Warp CEO · Changelog #555)

> 问题: "Warp 的 '每个命令 + 输出 = 一个 Block' 把终端从 stream 变成 document。HGC 的 /library/triage 现在是 stream (一个接一个), 打完的不能快速回看。"
>
> 方案: 打过的 clip 在底部 '已打标' 区堆叠 · 可 Cmd+Z 撤回 · 可 Shift+Click 批量改。

#### A-18 · Linear Design Team (2026-03 UI refresh)

> 问题: "Linear 2026 春季的 UI refresh 做了一件关键的事 — 把 header / nav / view controls 在所有页面完全一致。HGC 现在 dashboard 顶部一套、library 另一套、recipe 又另一套。"
>
> 方案: 统一 InternalTopBar: 左侧 breadcrumb / 中间 search (Cmd+K 触发器) / 右侧 user + notifications。

#### A-19 · David Hoang (Webflow · design podcast)

> 问题: "Webflow 的 'Preview' 按钮是一键 toggle (P), 从编辑态切阅读态。HGC 的菜谱没有 preview — 直接编辑。"
>
> 方案: 菜谱详情 top-right 有 [ Edit | Preview ] 切换 · P 键切换 · Preview 模式下字体自动放大 20%, 更像"读"。

#### A-20 · Soleio Cuervo (ex-Dropbox · 设计领导)

> 问题: "Dropbox 学到的教训: 'upload' 按钮是路径的终点, 不是起点。HGC /tools/import 还是把 import 当按钮。应该是 drag anywhere, 自动识别。"
>
> 方案: 全局 drop zone — 用户可以在任何 /internal 页面拖文件进来, 自动创建 clip, 进入后台处理 (toast 通知)。

#### A-21 · Brandon Chu (Shopify · "The Black Box of Product Management")

> 问题: "Shopify admin 的 'home' 是一个 Feed, 不是 dashboard. Feed 按时间顺序列出所有发生的事。HGC /dashboard 没有时间轴, 不知道昨天 Frida 打了什么标。"
>
> 方案: /dashboard 右侧固定 "Activity Feed" 组件 · 实时流 · 头像 + 动词 + 对象 (Frida 标记 clip_123 为 hook, 3 分钟前)。

#### A-22 · Christopher Robbins (ex-Apple HIG team)

> 问题: "Apple HIG 的第一条是 'clarity'. HGC 的 /login 按钮写 'Sign In'. 下面的表单里 email / password 之间没有视觉分组。按钮的颜色是 ink, 和周围背景对比只有 7.2:1 — 勉强过 WCAG AA, 但没有 accent。"
>
> 方案: 用 red (#c1272d) 作为 primary button · 和 paper 对比 9.4:1. 输入框之间 gap-4 → gap-6。

### 1.2 · 团队 B · 20 RPG 游戏设计师 · 20 条 critique

#### B-01 · Masayoshi Sutou (Persona 5 UI director)

> 问题 (Sutou 真实设计哲学: 每次按菜单键都要有 micro-narrative): "HGC 从 sidebar 点 Recipe 进入 /tools/recipe, 进入时没有任何'性格'。Persona 5 按菜单键, 字会飞进来, 背景会滑, 每次都是一出小戏。"
>
> 方案: 路由切换时用 View Transitions API · sidebar item 飞到页面标题位置 · 背景右侧 40% 斜切入场 (motion: x: '30%' → 0, 0.4s)。

#### B-02 · Masayoshi Sutou (Persona 5)

> 问题: "Sutou 访谈说: 早期 P5 UI 太 aggressive, 遮挡了游戏本身, 所以 toned down. HGC /library/triage 的 COMBO 动画很大, 遮挡了下一张卡。"
>
> 方案: COMBO 数字飘在画面边缘, 不覆盖卡片。尺寸减半, 但字重加到 900, 保持气势。

#### B-03 · Robert Kurvitz (Disco Elysium · Lead Writer/Designer)

> 问题: "Disco Elysium 的天才是: skill 不是数字, 是'内心的声音'. 当你面对一个 check, '逻辑' 这个 skill 会说话 · 给你 context。HGC 的 Freddy 人设是一个 static 卡片, 不是角色。"
>
> 方案: Dashboard 的 Freddy 卡片加 'Freddy 在想...' 随机浮现字幕 — 从 5 原则数据库随机一条 '今天不提糖, 先讲人。' · 每日刷新。

#### B-04 · Swen Vincke (Larian · BG3 director)

> 问题: "BG3 character sheet 被社区 mod 是因为信息分散 3-4 屏。HGC Library Split 页的 '片段信息' 也分散 (顶部标题 / 右侧 tag / 底部 duration / 左侧 thumbnail)。"
>
> 方案: Split 页右侧 Inspect Panel 垂直统一: 标题 → duration → 时间码 → AI tag → human tag → 使用记录。

#### B-05 · Greg Kasavin (Hades · Supergiant creative director)

> 问题: "Hades 的 boon selection 每次只给 3 个选项, 每个描述 2 行。选择是仪式。HGC /library/triage 每次给用户 1 个 clip 和 10 个 tag 按钮 — 这是考试, 不是游戏。"
>
> 方案: Triage 界面底部 tag bar 从 10 键 QWERTYUIOP 改成 '推荐 3 + 更多' · AI 给 3 个最可能的 tag 大按钮 · 按数字 1/2/3 · 其他折叠。

#### B-06 · Greg Kasavin (Hades)

> 问题: "Hades 每次死 (Escape Failed) 不是惩罚, 是下一次的开始 — 房间布局变, Nyx 有新对话。HGC 打标 skip 当前 clip 就是跳过, 没有'回来遇见新东西'的感觉。"
>
> 方案: skip 的 clip 在 Dashboard 出现 '被跳过, 但...' 随机彩蛋 — 例: "Freddy 在这条里提了墨西哥朋友的名字, 可能用于 O-04?"

#### B-07 · Hideo Kojima (Death Stranding · UI design thinking)

> 问题: "Death Stranding 的地图是互动叙事 — 玩家放置梯子会被别人用。HGC 的 /library 其他成员打的标我看不见历史。"
>
> 方案: Split 页时间码下显示之前打过标的人 (小头像), hover 看他们的 tag。'Frida 3 天前标了 hook 在 0:12'。

#### B-08 · Yoko Taro (NieR: Automata · director)

> 问题 (来自 PlatinumGames 官方 blog): "Yoko Taro 第一次 UI 会议说 '加点奇怪的'. 早期太 realistic 了。HGC 整站 '规范' 的过分 — 没有任何 'weird delight'。"
>
> 方案: Dashboard 左下角随机出现 Orbie (龙虾吉祥物) · 3% 概率自动说一句话 ("今天 Freddy 笑得好真"), 然后淡出。不是 always on, 是 rare encounter。

#### B-09 · CD Projekt Red UI team (Cyberpunk 2.0)

> 问题: "2.0 update 把 radial menu 做成 hold-Q 按钮弹出。HGC 所有 action 都要鼠标点。"
>
> 方案: 长按 Space 弹出 radial (4 向): ↑ Upload / → Search / ↓ New Recipe / ← Triage. 松开执行。

#### B-10 · FromSoftware UI team (Elden Ring)

> 问题: "FromSoftware 原则: HUD 只在需要时显示 (血低才显示血条)。HGC /library 网格视图每个 card 都有 duration / tags / status — 视觉噪音大。"
>
> 方案: Grid 默认只显示缩略图 + 时长。hover 才出 tag / status overlay (opacity: 0 → 0.95, 0.2s)。

#### B-11 · Keita Takahashi (Katamari · lead designer)

> 问题: "Katamari 的 bizarre 是核心 — 玩家在'收集'中找到怪诞快感。HGC 打标页的音效 (已有 sfx.ts) 是 generic click。应该有 '咕噜' '叮叮' 这种味道。"
>
> 方案: sfx.ts 增加 5 种变奏 — tag-hook.mp3, tag-dismiss.mp3, combo-3.mp3, combo-5.mp3, combo-10.mp3. 10+ combo 解锁 Orbie 从角落蹦出 2 秒。

#### B-12 · Rolando Caloca (FromSoftware · rendering/animation)

> 问题: "Elden Ring 的死亡动画其实是解脱 — 游戏告诉你 '这是正常的'. HGC 的错误 toast 是红色 X, 报错即失败。"
>
> 方案: 错误改成 Freddy 图标 + 情境语: "糖掉了。再拿一颗?" + retry 按钮。降低羞耻感。

#### B-13 · Hazelight team (It Takes Two · co-op)

> 问题: "It Takes Two 的核心是 '两人各做一半'. HGC 没有任何 co-op 专属体验 — Frida 和 Hank 都在独自打标。"
>
> 方案: Triage 增加 'Together mode' · 两人在同一队列, 分屏左右, 各自打自己的 · 打完一条对方 UI 有视觉反馈 (光标闪一下)。

#### B-14 · Ubisoft Reflections (Watch Dogs Legion UI)

> 问题: "Legion 的角色系统有 NPC 情绪状态。HGC 的人物 (TZ/Frida/Hank/Freddy) 只有头像, 没有'今天状态'。"
>
> 方案: Dashboard Members 卡 · 每人头像下加 mood dot (green=online, yellow=focused, red=do not disturb)。Supabase Realtime presence 驱动。

#### B-15 · Double Fine (Psychonauts · Tim Schafer)

> 问题: "Psychonauts 2 的每个关卡有独立 art direction. HGC 所有 internal page 视觉统一到一模一样, 缺少 '每个功能是一个世界' 的心智模型。"
>
> 方案: /library/triage 改成 '后厨打标台' · 加 subtle 木纹背景 · /tools/recipe 改 '食谱本' · 淡纸质感 · /intel 改 '情报地图' (未来) · 浅色等高线。

#### B-16 · Supercell (Clash Royale card UI)

> 问题: "Clash Royale card 的 rarity 有颜色 (common/rare/epic/legendary). HGC 的 clip 没有稀有度 — 但明明 Freddy 人设抓到的 '真瞬间' 比废片珍贵 100 倍。"
>
> 方案: Clip 卡片加 rarity 边 — 普通 (无边) / 好 (金边 1px) / Gold (金边 2px + 微发光)。打标时可升级。

#### B-17 · Nintendo UX team (Zelda BotW cooking)

> 问题: "BotW 的 cooking 是实时模拟 — 扔食材进锅, 会看见冒泡, 听见声音, 拿到一个 dish。HGC 的 menu 叫 '菜谱库' 但完全没有 '煮' 的动作。"
>

### 2.1 · 冲突与共识

#### 冲突 1 · 极简 vs 表达

- **团队 A** (Linear/Superhuman): "越少越好 · 100ms 优先"
- **团队 B** (Persona 5/NieR): "没有'怪'没有叙事, 就是工具, 不是伙伴"
- **团队 C** (Flow/Hooked): "中间路线 — 极简结构 + rare 惊喜"

**裁决**: 默认极简, 小概率 (1-5%) 惊喜。Orbie 登场频率 = 每 100 条一次。核心路径 (打标/播放/搜索) 必须 ≤ 100ms。

#### 冲突 2 · 静态 KPI vs 叙事 Feed

- **A-21** (Brandon Chu): Dashboard 应该是 Feed
- **A-10** (Jason Fried): Dashboard 应该是 Today's Decision
- **Karri Saarinen**: 两者都要 — Decision 在顶, Feed 在侧

**裁决**: Dashboard = Top: Today's Decision (1 张大卡) + Right: Activity Feed (窄栏) + Bottom: KPI Sparklines。

#### 冲突 3 · 键盘 vs 鼠标

- **A 组大多数**: 键盘优先
- **B-09** (Cyberpunk): radial menu (鼠标/手柄)
- **C-16** (DaVinci): J K L + 鼠标 scrub 并存

**裁决**: 键盘是 first-class · 所有鼠标交互都有键盘等价物。Triage 页 QWERTYUIOP 键帽保留 · 增加 J K L 作为 review 导航。

#### 共识 · 7 大公理

1. **100ms 为神圣极限** (Vohra, Saarinen, Apple HIG 共同)
2. **Cmd+K 为所有应用的 OS** (Raycast, Linear, Warp, Superhuman)
3. **反馈 = 触觉 + 听觉 + 视觉三合一** (Apple HIG, Hades, P5)
4. **信息在需要时显示** (Elden Ring, Superhuman, Progressive Disclosure)
5. **多人存在感 (presence) 是现代工作必然** (Figma, Focusmate, Flow Club)
6. **变化奖励胜过固定奖励** (Hooked, Hades, Duolingo)
7. **页面是世界, 不是画布** (Persona 5, Psychonauts, Craft)

### 3.2 · 架构决策

#### ADR-01 · 路由 + 渲染

**决定**: 所有 /internal 用 Server Components + Client islands。 对外页用 PPR。

```tsx
// /app/page.tsx (对外首页)
export const experimental_ppr = true;
// 静态 shell 立即返回 · dynamic parts stream in
```

```tsx
// /app/internal/library/triage/page.tsx
import { TriageClient } from './TriageClient';
import { getCurrentQueue } from '@/lib/db/clips';

export default async function Page() {
  const initialQueue = await getCurrentQueue();
  return <TriageClient initialQueue={initialQueue} />;
}
```

**Why**: Saarinen — 静态部分是 shell, dynamic 部分是内容。PPR 让 LCP 瞬时。Internal 页需要实时数据 → client island 用 supabase realtime。

**Why**: Redux 太重 · Context 太泛 · Zustand 3 行起步 · 易调试。

#### ADR-03 · 动画引擎

**决定**: Motion (ex-Framer Motion) 作为 React 动画的 90% · Rive 处理 Orbie 等复杂互动 · CSS @starting-style 处理入场 · View Transitions API 处理页面间。

```tsx
// 动画库分工
import { motion } from 'motion/react';           // 90% 场景
import { useRive } from '@rive-app/react-canvas'; // Orbie + 复杂互动
// @starting-style                                // 元素入场 (Tailwind 4)
// document.startViewTransition()                 // 页面切换
```

**Why**: Motion 支持 hardware-accelerated 120fps · Rive 的 state machine 让 Orbie 可以对 JS 事件反应。

#### ADR-04 · 命令系统

**决定**: cmdk (pacocoursey/cmdk) · 基于 Radix UI · 是 Linear/Raycast-style 标准。

#### ADR-05 · 实时协作

**决定**: Supabase Realtime Channels · Presence + Broadcast 双通道。

```ts
// src/lib/realtime/presence.ts
const channel = supabase.channel(`room:${page}`, {
  config: { presence: { key: userId } }
});

channel
  .on('presence', { event: 'sync' }, () => {
    const state = channel.presenceState();
    // 更新其他人的头像
  })
  .on('broadcast', { event: 'cursor' }, ({ payload }) => {
    // 更新其他人的光标位置
  })
  .subscribe();

// 发送自己的 cursor (throttle 60fps)
channel.send({ type: 'broadcast', event: 'cursor', payload: { x, y } });
```

**Why**: Supabase Realtime 官方有 Next.js cursor 组件, 免费 plan 也支持。
